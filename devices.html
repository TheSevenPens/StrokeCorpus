Devices compared

A reading is not a measurement. The corpus keeps every reading a driver handed over, and a driver can hand over the same value more than once. This page says, for each device the corpus has recordings of, how often each channel actually carried a new value.

How often a channel carries a new value

Tablet Backend Firmware Recordings Readings / s Position Pressure Pressure takes a new value Pressure updates / s Pressure levels

Position and Pressure are the share of consecutive in-contact readings that differed from the one before. Readings / s is measured on the host clock over whole strokes, so it is only given for recordings that carry one. A dash means the recordings did not carry the column, or had too few pressure changes for a pattern to be stated.

Why it matters

A brush engine that treats every reading as an independent sample of the pen is wrong about a device that repeats a value. Pressure that changes on every second reading is half as many measurements as the reading rate suggests, and anything that differentiates it — how quickly pressure is rising, say — sees a number that is zero half the time and double the rest.

The pattern is not necessarily the pen. It is in the readings as this recording path delivered them, so it can come from the tablet, its firmware, the driver or the way the driver was read. The corpus can say that it is there and how often; telling those apart needs the same pen recorded through more than one of them, which is what a second device or backend is for.

Each recording's own page shows the same measurements, with the length of every hold. The method is in FORMAT.md.
